# AQF-T Production — 多路径统一框架


## 核心原则

```
两条路, 三统一:

  统一风控: Risk模块对两条路一视同仁
  统一执行: 同一个QMT下单, 同一个账户
  统一复盘: 同一个Review归因

  分开的只有: 信号生成逻辑和参数
```

---

## 一、风控 — 统一 (不可绕过)

```
两条路都经过同一个 Risk:

路径A(回封板)信号 → Risk审批 → APPROVE/ADJUST/REJECT → QMT
路径B(半路)信号   → Risk审批 → APPROVE/ADJUST/REJECT → QMT

共享风控:
  单票 ≤ 15%
  总仓位 ≤ 70%
  日亏 ≥ 3% → 停当日
  退潮期 → 两条路都禁止买入
  Kill Switch → 两条路都停止

不共享的:
  路径A 回封板专属: 进场后再炸板>10min → 强制卖出
  路径B 半路专属:   涨幅回落到<3% → 止损
```

## 二、参数 — 分路径 + 共享

```
共享参数 (config/system.yaml):
  risk:
    max_single_position: 0.15
    max_total_position: 0.70
    max_daily_loss: -0.03
  execution:
    slippage_bps: 20
    delay_ms: 200

路径A 专属:
  strategy:
    reseal:
      volume_ratio_threshold: 0.7     # 缩量标准
      time_threshold_min: 10          # 快速回封标准
      linkage_min: 1                  # 联动最少跟风数
      position_pct_main: 0.15         # 主线仓位
      position_pct_sub: 0.08          # 次线仓位

路径B 专属:
  strategy:
    alpha:
      lgbm_confidence_threshold: 0.65  # Alpha最低置信度
      timing_threshold: 0.60           # 择时最低分
      position_pct: 0.10               # 半路仓位(<回封板)
```

## 三、回测验证 — 同引擎, 不同信号源

```
统一回测引擎:
  事件驱动 / A股规则(T+1/涨跌停/费率/滑点) / 同一套代码

回测路径A (回封板):
  数据: 历史涨停数据 + L2回放
  关键: 需要L2历史数据才能回测 (炸板→回封)
  没有L2历史 → 跳过, 直接模拟盘验证

回测路径B (半路/接力):
  数据: 日K线 + 分钟K线 (不需要L2)
  关键: LGBM/XGBoost需要3年历史训练
  可回测: 用历史数据跑LGBM趋势判断 + 模拟拉升买入

回测指标 (两条路共用):
  夏普 > 1.2 / 最大回撤 < 20% / 胜率 > 45% / 盈亏比 > 2.0
```

## 四、模拟盘 — 先跑路径B, 再跑路径A

```
模拟盘阶段 (Paper Trading, 真实行情+模拟成交):

Phase 1: 先跑路径B (1个月)
  原因: 不需要L2, 日K线+LGBM就可跑
  验证: 趋势判断准确率, 半路封板率

Phase 2: 再跑路径A (1个月)
  原因: 需要L2实时数据, 观察回封板信号
  验证: 炸板分类准确率, 回封确认胜率

Phase 3: 两条路同时跑 (2周)
  验证: 不会互相干扰, 总仓位不超限

模拟期间:
  QMT Paper模式 (本地撮合)
  风险检查完整运行
  每日复盘 + 因子归因
```

## 五、实盘 — 统一账户, 分路计数

```
实盘阶段 (QMT Live):

  同一个账户, 同一个QMT, 同一个Risk

  路径A持仓: 最多2只, 每只≤15%
  路径B持仓: 最多3只, 每只≤10%
  总仓位上限: 70%
  
  优先级 (仓位冲突时):
    路径A > 路径B (回封板确定性更高)
    
  Review归因:
    每条交易标记路径来源 (path=A or B)
    分别统计胜率/盈亏比
    持续对比: A vs B 哪个更赚钱?
    资金分配动态调整: 哪个路径赚钱多就多分配仓位
```

## 六、统一 vs 分开 对照表

```
                共享                     分开
─────────────────────────────────────────────────
市场感知    情绪周期/梯队/题材            —
Risk        限额/熔断/KillSwitch          —
Execution   QMT/账户/费率                 —
信号生成    —                         路径A(Perception) / 路径B(LGBM+XGBoost)
参数        —                         路径A(回封参数) / 路径B(Alpha参数)
回测        事件驱动引擎                 数据(L2 vs 日K)
复盘        统一归因框架                 分路径统计
仓位        总上限70%                    A优先于B
```

## 七、风险控制

```
两条路的仓位冲突处理:

  总仓位已达70%:
    路径A有信号 → 路径B减仓给A让路 (A优先)
    路径B有信号 → 不执行, 等仓位降下来
    
  退潮期:
    两条路都禁止买入
    已经持有的 → 按各自止损规则离场
```

## 八、验证路线图

```
Phase 1: 回测
  路径B: LGBM日K回测 (3年历史)
  路径A: L2历史回测 or 跳过 (模拟盘直接验)

Phase 2: 模拟盘
  Phase 2a: 路径B单独跑 1个月
  Phase 2b: 路径A单独跑 1个月
  Phase 2c: 两条路同时跑 2周

Phase 3: 实盘
  ≤10万, 人工监控, 两条路同时
  路径A仓位 > 路径B仓位
  持续对比A vs B绩效
```
