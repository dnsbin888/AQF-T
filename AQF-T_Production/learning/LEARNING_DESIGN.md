# 06 Learning — 四维模型框架


**状态:** 设计阶段 | **验证:** 待训练后确认

---

## 四维决策 Pipeline (串联, 非Ensemble)

```
选什么 → 何时进 → 做多少 → 有新信息吗
 LGBM    XGBoost   Regime    Event
   │        │        │         │
   └────────┴────────┴─────────┘
                │
          最终决策 → Risk审批 → QMT执行
```

## 四个模型

### 维度1: Alpha — LightGBM (趋势预测)

```
数据: 日K线 + 100因子 (技术30 + Alpha30 + 情绪20 + 资金20)
标签: 未来N日收益率
输出: 方向(BUY/SELL/HOLD) + 概率
问题: "会涨吗?"

训练: 3年+历史日线, 月度滚动重训
验证: IC > 0.05, AUC > 0.65
```

### 维度2: Timing — XGBoost (L2择时)

```
数据: L2逐笔成交 + 十档盘口 + 委托队列 + 大单统计
标签: 未来30/60分钟收益率 (二分类: NOW/WAIT)
输出: NOW / WAIT + 置信度
问题: "现在进吗?"

训练: 3个月L2历史, 日度滚动
验证: 分类准确率 > 55%
```

### 维度3: Regime — 规则引擎 (情绪周期)

```
数据: 全市场统计 (涨停数/跌停数/连板高度/炸板率/北向)
方法: 情绪值公式 + 四阶段判断
输出: 情绪周期 + 仓位系数

情绪值 = 涨停×2 - 跌停×3 + 连板×5 + 北向×10

冰点(<20) → 仓位20%, VolumePrice试错
回暖(20-50) → 仓位50%, Dragon+Sentiment
高潮(50-80) → 仓位70%, Dragon重仓
退潮(>80或炸板率>40%) → 仓位20%, 禁止买入
```

### 维度4: Event — LLM API (事件分析)

```
数据: 公告/新闻/政策/龙虎榜/社交媒体
方法: DeepSeek/Qwen API 解析
输出: 事件信号 + 影响方向 + 紧急程度

示例:
  政策利好公告 → 影响方向=正面 + 紧急程度=高
  个股利空公告 → 影响方向=负面 + 紧急程度=紧急
```

---

## 融合规则

```
LGBM=BUY + XGBoost=NOW + Regime=高潮(满仓) + Event=利好
  → 全仓买入, 高置信度

LGBM=BUY + XGBoost=WAIT + Regime=退潮(限仓) + Event=无
  → 不买 (Regime否决)

LGBM=BUY + XGBoost=NOW + Regime=回暖(仓位50%) + Event=利空
  → 半仓 (Event降级)

Regime 优先级最高 — 退潮期无视所有买入信号
Event 为最后调节 — 突发信息可降仓/暂停
```

## 四个模型的关系

```
不是Ensemble — 不做同一件事, 不投票
是Pipeline  — 各做各的, 串联决策

1. 不冲突 — 预测四个不同东西
2. 不重合 — 四组完全不同数据
3. 可降级 — 任一模型失效不影响其他三个
```

## 验证计划

```
Phase 1: LGBM趋势预测
  回测: 3年A股日线, 滚动训练
  指标: IC > 0.05, AUC > 0.65

Phase 2: XGBoost L2择时
  回测: 3个月L2数据
  指标: 分类准确率 > 55%

Phase 3: 两模型联合
  LGBM=BUY + XGBoost=NOW → 模拟成交
  对比: 单独LGBM vs LGBM+XGBoost → 夏普是否提升?

Phase 4: 四维全融合
  LGBM + XGBoost + Regime + Event
  模拟交易1个月 → 指标达标 → 实盘验证
```
