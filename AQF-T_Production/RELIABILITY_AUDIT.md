# AQF-T Production — 可靠性与可行性审计


## 一、完整交易流程 (逐秒推演)

```
8:00  系统自检
      QMT连接? → 失败→钉钉告警→重试3次→放弃
      L2数据可用? → 不可用→降级到akshare→告警

9:15  盘前竞价
      akshare拉取竞价数据
      Market Regime预判 (基于昨日数据+竞价信号)
      → 退潮? 今天不交易, 只监控

9:30  开盘
      QMT L2数据流启动 (逐笔成交+十档盘口)
      涨停池初始化 (空)

9:30-10:00 首板密集出现
      每只涨停 → QMT推送到涨停池
      首板: 只监控, 不交易 (等二板确认 or 炸板回封)

10:00-11:30 炸板+回封观察期
      涨停池中某只炸板 → 触发炸板分类

      炸板分类流程:
        ① 计算: 炸板后跌幅 (当前价 vs 涨停价)
        ② 判断: <5%横盘 → 继续观察 / >7%下坠 → 放弃
        ③ L2监控: 买盘承接? 大单接货?
        ④ 分类: 洗盘型(等回封) or 诱多型(放弃)
        
        耗时: <500ms (L2数据实时)

      洗盘型 → 等回封 → 回封确认:
        ① 缩量: 回封1分钟量 / 一封1分钟量 < 0.7?
        ② 快速: 炸板→回封 < 10分钟?
        ③ 联动: 同板块有跟风?
        
        满足≥2 → 生成Path A信号 → Risk审批 → QMT下单
        耗时: <200ms

13:00-14:30 下午板
      同上午逻辑
      下午板优先级降低 (封板率只有上午50%)

14:30-15:00 尾盘
      尾盘板 → 不参与 (封板率低, 次日溢价差)
      已有持仓 → 检查是否连板中断 → 尾盘清仓

15:00 收盘
      停止所有买入信号
      拉取龙虎榜数据
      日终复盘
```

## 二、关键节点可靠性评估

### 节点1: Market Regime 判断

```
可靠性: ⭐⭐⭐⭐

验证方法:
  回测历史数据 (2022-2025) → 手动标注情绪周期 → 对比引擎输出
  目标: 四阶段分类准确率 > 80%

潜在问题:
  - 情绪值公式在极端行情下可能失效 (如2024年初微盘股危机)
  - 北向资金单日大幅流入/流出可能扭曲信号
  
缓解:
  - 加入炸板率作为辅助判断 (炸板率>50%→强行退潮)
  - 连续2天满足退潮条件才确认 (防单日噪音)
```

### 节点2: 炸板分类 (洗盘 vs 诱多)

```
可靠性: ⭐⭐⭐ (需实盘验证)

验证方法:
  模拟盘收集100次炸板 → 人工标注(洗盘/诱多) → 对比引擎分类
  目标: 分类准确率 > 70%

潜在问题:
  - 5条洗盘条件部分依赖L2数据 (大单接货判断)
  - L2数据噪声大 (拆单/对倒会干扰)
  
缓解:
  - ≥3条才判定洗盘 (严格标准, 宁可错过不可错判)
  - 不确定时默认"不参与" (保守)
```

### 节点3: 回封确认

```
可靠性: ⭐⭐⭐⭐ (2026数据验证: 胜率70-85%)

验证方法:
  回封质量分 vs 次日实际溢价 → 相关性检验
  目标: 高分(>0.7)回封的次日溢价显著 > 低分(<0.5)

潜在问题:
  - 缩量判断依赖L2实时数据 (回封瞬间量)
  - 联动判断需要板块实时涨速 (计算延迟)
  
缓解:
  - 满足≥2/3才进场 (严格)
  - 板块地位<0.4不参与 (过滤杂毛)
```

### 节点4: QMT执行

```
可靠性: ⭐⭐⭐⭐⭐ (已验证技术)

已验证:
  - miniQMT 500MB内存, 7×24稳定运行 (行业验证)
  - 沪市25ms/深市3ms 报单延迟
  - 个人实测200ms全链路

潜在问题:
  - 涨停板排队可能无法成交 (回封板二封同样有排队风险)
  - QMT客户端崩溃 (极小概率)
  
缓解:
  - 回封板二封: 炸板后流动性恢复, 成交概率 > 首封排队
  - 守护进程: QMT崩溃→自动重启
  - 钉钉告警: 异常即时通知
```

## 三、边界情况处理

### 场景1: 一字板 (无法参与)
```
检测: open=high=close=涨停价
处理: 不追, 等首次开板 (换手) 后再评估
```

### 场景2: 天地板
```
检测: 涨停→打开→跌停
处理: 板型=天地板, 直接放弃, Risk Score+50
```

### 场景3: 连续炸板 (炸3次+)
```
检测: reopen_count ≥ 3
处理: 放弃, 炸板太多说明分歧巨大
```

### 场景4: 尾盘回封 (14:45+)
```
检测: 回封时间 > 14:45
处理: 不参与, 尾盘板次日溢价差
```

### 场景5: QMT数据断流
```
检测: L2数据超过30秒无更新
处理: 暂停所有买入信号, 只监控
      数据恢复后重新初始化
```

### 场景6: 已持仓的票再次炸板
```
检测: 持仓中 + 炸板
处理: 不适用回封逻辑 (已有仓位)
      执行止损规则: >10分钟未回封→离场
```

## 四、可行性总结

```
Path A (回封板):
  可行性: ⭐⭐⭐⭐
  核心依赖: L2数据实时性 (QMT已验证)
  关键瓶颈: 炸板分类准确率 (需模拟盘验证)
  解决: 严格条件 + 保守策略 (不确定就不做)

Path B (半路):
  可行性: ⭐⭐⭐
  核心依赖: LGBM模型训练效果
  关键瓶颈: 训练数据质量 + 过拟合风险
  解决: 三目标标签 + 滚动重训 + 样本外验证

整体系统:
  可行性: ⭐⭐⭐⭐
  最大风险: 路径A的炸板分类需要实盘验证
           路径B的LGBM需要历史数据训练
  都已规划验证路径: 模拟盘→小资金实盘
```

## 五、上线检查清单

```
回测验证:
  ✅ Path B LGBM回测 (3年历史, IC>0.05)
  ⏳ Path A 回封板逻辑验证 (需要L2历史, or跳过)

模拟盘 (≥1个月):
  ⏳ 信号出现频率是否合理?
  ⏳ 成交率 (回封板二封能买到吗?)
  ⏳ 风控拒绝率
  ⏳ 炸板分类准确率

实盘 (≤10万):
  ⏳ 与模拟盘偏差 < 30%
  ⏳ 无系统崩溃
  ⏳ Kill Switch有效
```
