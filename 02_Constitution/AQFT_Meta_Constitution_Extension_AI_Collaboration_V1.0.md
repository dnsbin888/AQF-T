# AQF-T Meta Constitution Extension — AI Collaboration Governance Framework

Version: V1.0.0 | Status: ✅ FROZEN — Same Level as Meta Constitution
Date: 2026-07-28 | Priority: Same as MC-001~MC-010

---

## Mission

AQF-T 从 V3.0 开始，不再由单一 AI 参与设计，而进入 **Multi-AI Collaborative Architecture Era**。参与者可能包括 ChatGPT、Claude、Gemini、DeepSeek、Human Architect 等。必须建立统一知识治理体系，保证任何 AI 的设计都：可解释、可追溯、可验证、可协同、可回滚。

---

## MC-011: Architecture Changes Must Be Traceable

任何 Architecture 变更必须 100% 可追溯。

**禁止：AI 直接修改 Blueprint。**

允许：Proposal → Review → Merge → Archive

所有变更必须拥有唯一编号（ARC-XXXXXX），永久保留。

---

## MC-012: Architecture Synchronization First

所有 AI 在开始设计前，必须同步 ACL + DSP + WMP。**禁止基于过期 Blueprint 工作。**

---

## MC-013: Proposal Before Modification

任何 AI 不得直接修改正式 Blueprint。必须：Proposal → Architect Review → Merge。

---

## Architecture Change Proposal (ACP)

任何 AI 修改 Blueprint 必须先生成 ACP：

```
ACP-ID: ACP-000031 | Author: Claude | Date: 2026-08-03
Module: Opponent Model | Priority: P1 | Evidence: A
Reason: 新增 Participant Intent
Affected: Decision, Memory, World Model, Risk
Backward Compatible: YES | Architect Review: Required
```

未经 ACP 不得修改正式 Blueprint。

---

## Architecture Change Log (ACL)

所有 ACP 审核完成后进入 ACL。以后任何 AI 首先阅读 ACL，而不是重新阅读全部文档。

---

## Impact Analysis

每次修改自动生成 Impact Report：

```
Changed: Opponent → Direct: Decision → Indirect: Memory → Potential: World Model → None: Execution
Level: Critical / Major / Minor / None
```

---

## Architecture Fingerprint

每个模块拥有 Fingerprint（如 WM-3.0.2: 14 interfaces, 4 dependencies, Evidence A+, C-002）。任何修改自动产生 Impact Report。

---

## AI Collaboration Contract

所有 AI 必须遵守：不允许直接删除/覆盖/修改Constitution/绕过Review/修改Immutable Core。必须提交Proposal、说明来源、说明影响、说明验证、等待Merge。

---

## Module Ownership

每个模块定义 Owner（最终责任人）、Reviewer、Contributor。Owner 不是唯一开发者，而是最终责任人。

---

## Working Memory Package (WMP)

由于 ChatGPT/Claude/Gemini 彼此无法共享真正的 Memory，建立 WMP：

```
WMP: Current Blueprint | Current Constitution | Current Fingerprint |
     Current ACL | Current Roadmap | Known Issues | Evidence Library |
     Pending Proposal | Frozen Modules
```

每次开始工作先读取 WMP，结束更新 WMP。所有 AI 保持一致上下文。

---

## Design Synchronization Package (DSP)

每次 Merge 自动生成 DSP。以后不用重读 200 页，只读 DSP，5 分钟同步完成。

---

## Knowledge Synchronization Rule

任何 AI 开始工作：Read DSP → Read ACL → Read Current Constitution → Read Pending Proposal → Start Design。结束反向：Proposal → Impact → ACL → DSP → Merge。整个团队永远同步。

---

## Architect Review Pipeline

Architect 只 Review 四件事：Evidence → Impact → Consistency → Validation。Review 时间从 2 小时降到 15 分钟。

---

## AI Collaboration Workflow

```
AI → Read WMP → Read ACL → Read DSP → Proposal → Impact → Architect Review → Merge → Update ACL → Update DSP → Update WMP
```

任何 AI 完全一致。

---

---

## Final Goal

AQF-T 的目标不是让多个 AI "一起写文档"。而是建立一个可持续演进的 AI 协同架构治理系统：

- 任何设计都有证据（MC-001~MC-007）
- 任何变更都有记录（MC-011）
- 任何 AI 都保持同步（MC-012）
- 任何修改都经过提案与审查（MC-013）
- 任何决策都可以回溯、解释、验证和回滚
