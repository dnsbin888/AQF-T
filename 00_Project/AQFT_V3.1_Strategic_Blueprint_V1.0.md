## 一、核心战略调整

V3.0 已完成 Understand→Execute→Learn→Compete。V3.1 最大风险不是能力不足，而是 **Architecture Complexity Growth**。

**V3.1 总原则：Validate Before Expand。** 不是继续增加智能，而是证明已有智能是否有效。

## 二、Complexity Budget Principle

复杂度必须产生收益。任何模块必须回答：增加多少复杂度？获得多少能力提升？是否超过维护成本？

`ROI = Capability_Improvement / Complexity_Cost`

## 三、原创 vs 外部成熟模型

禁止"为了原创而原创"。三种策略：

**Strategy A — Buy First（优先成熟方案）**：Transformer / Bayesian Model / Knowledge Graph / Vector DB / Time Series / Calibration 等已有行业方案

**Strategy B — Build When Unique（保留原创）**：仅当市场无成熟替代、解决A股特殊问题、与核心认知链一致。保留：S(t)→B(t)→R(t)→Ω、Decision Quality≠Trading Result、Pattern→Knowledge

**Strategy C — Hybrid（优先）**：成熟模型负责基础能力，AQF-T负责认知融合

## 四、Technology Admission Framework (TAF-001)

Stage 1: Technology Identification → Stage 2: Evidence Review (MC-001~010) → Stage 3: Compatibility Analysis → Stage 4: Benchmark Test (A/B/C) → Stage 5: Decision (KEEP/REPLACE/MERGE/SIMPLIFY/REMOVE)

## 五、模块删除规则

任何删除必须经过 Architecture Retirement Review：Current Value → Replacement Analysis → Historical Importance → Future Option Value → Owner Approval

## 七、AQF-T 定位调整

以前：Build More Intelligence。现在：Build Better Intelligence。不以模块数量衡量智能，以经过验证的有效能力衡量智能。

## 八、V3.1 目标

Evidence→Validation→Knowledge→Decision→Evolution。从"设计一个智能交易系统"升级为"建立一个能够持续验证、吸收、淘汰、进化的交易智能生命系统"。
