# 第一章 测试体系定位


Test 模块是 AQF-T 质量保障中心。覆盖：单元测试 → 集成测试 → 回测验证 → 模拟交易 → 压力测试 → 上线验证。

**上线铁律：任何模块必须通过对应层级测试。未通过→不得进入下一阶段。**

---

# 第二章 测试层级


```
L1 单元测试    →  单模块功能正确性
L2 集成测试    →  模块间接口正确性
L3 回测验证    →  策略历史表现
L4 模拟交易    →  实时数据+模拟执行
L5 压力测试    →  极端场景
L6 上线验证    →  小额实盘
```

# 第三章 单元测试


## 3.1 覆盖要求

| 模块 | 覆盖率目标 | 核心测试项 |
|------|:---:|------|
| 03_AI_Brain | ≥80% | Prediction输入→输出正确性 / Sentiment情绪周期判断 / Fusion权重计算 |
| 04_Strategy | ≥80% | Dragon龙头识别条件 / 信号格式完整性 / 策略选择逻辑 |
| 05_Risk | ≥90% | 风险评分公式 / APPROVE/ADJUST/REJECT决策 / 限额检查 |
| 06_Execution | ≥90% | T+1规则 / 涨跌停规则 / 手续费计算 / 订单状态机 |
| 07_Data | ≥80% | 数据清洗 / Schema验证 / 异常检测 |
| 08_Parameter | ≥80% | 参数生命周期 / 变更管理 / 回滚逻辑 |

## 3.2 游资特化测试用例

```
Sentiment Engine 测试:
  ✅ 涨停100家+跌停5家+连板7 → 情绪值=100×2-5×3+7×5=220 → 高潮期
  ✅ 涨停10家+跌停40家 → 情绪值=10×2-40×3=-100 → 冰点期
  ✅ 炸板率60% → Sentiment Risk ≥ 60

Dragon Strategy 测试:
  ✅ 连板3+题材涨停5+封单/流通>5% → 识别为龙头
  ✅ 连板1+题材涨停2 → 不识别为龙头
  ✅ 炸板10分钟 → 触发卖出信号

Risk Engine 测试:
  ✅ Risk Score=25 → APPROVE
  ✅ Risk Score=60 → ADJUST, 仓位×0.5
  ✅ Risk Score=80 → REJECT
  ✅ 退潮期+BUY信号 → REJECT
  ✅ 日亏损-2.5% → 熔断触发
```

# 第四章 集成测试


## 4.1 核心链路测试

```
Link 1: Data → AI Brain
  输入: 模拟行情数据 → 预期: AI Brain返回有效PredictionOutput

Link 2: AI Brain → Strategy
  输入: FusionOutput → 预期: Strategy返回有效TradingSignal

Link 3: Strategy → Risk
  输入: TradingSignal(BUY) + 高风险环境 → 预期: Risk返回REJECT

Link 4: Risk → Execution
  输入: APPROVE → 预期: Execution生成Order
  输入: REJECT → 预期: Execution拒绝执行

Link 5: Execution → Feedback
  输入: Order FILLED → 预期: Data存储TradeRecord + Experience记录
```

## 4.2 全链路端到端

```
完整流程:
  模拟行情 → AI预测 → 策略信号 → 风控审批 → 模拟下单 → 反馈存储

验证:
  ✅ 链路无中断
  ✅ 数据格式各环节一致
  ✅ 异常环节不污染下游
```

# 第五章 回测验证


## 5.1 回测要求

```
数据: 至少3年历史数据 (覆盖牛/熊/震荡)
频率: 日线 + 60分钟
约束:
  ✅ T+1 当日买次日卖
  ✅ 涨跌停 涨停买不进/跌停卖不出
  ✅ 真实手续费 (佣金+印花税+过户费)
  ✅ 滑点 0.1%
  ✅ 最小交易单位 100股
```

## 5.2 评价指标

| 指标 | 通过阈值 | 说明 |
|------|:---:|------|
| 年化收益 | > 15% | 绝对收益基准 |
| 夏普比率 | > 1.2 | 风险调整后收益 |
| 最大回撤 | < 20% | 极端风险控制 |
| 胜率 | > 45% | 交易准确率 |
| 盈亏比 | > 2.0 | 平均盈利/平均亏损 |
| Calmar比率 | > 1.0 | 年化/最大回撤 |

## 5.3 游资特化回测场景

```
场景1: 高潮期打板
  条件: 情绪周期=高潮期 + 识别龙头 + 二板接力买入
  验证: 连板成功率 > 40%

场景2: 退潮期防御
  条件: 情绪周期=退潮期
  验证: 空仓或轻仓 + 无买入信号

场景3: 炸板处理
  条件: 持有涨停股 + 炸板
  验证: 10分钟内卖出 + 无亏损扩大

场景4: N字反包
  条件: 前3日下跌 + 第4日放量上涨
  验证: 反包成功率 > 35%
```

# 第六章 模拟交易


## 6.1 Paper Trading 要求

```
环境: 真实行情 + 模拟Broker + 真实费率
周期: ≥ 1个月
验证:
  ✅ 信号生成正常
  ✅ 风控审批正常
  ✅ 模拟成交逻辑正常
  ✅ 持仓/资金计算准确
  ✅ 无明显逻辑bug
```

## 6.2 模拟vs回测差异检查

```
如果 Paper Trading 结果与回测偏差 > 30%:
  → 检查: 是否用了未来数据? 手续费计算是否准确? T+1是否生效?
```

# 第七章 压力测试


## 7.1 极端场景

| 场景 | 模拟条件 | 验证目标 |
|------|---------|---------|
| 全市场暴跌 | 跌停 > 500家 | Kill Switch触发 / 熔断生效 |
| 个股天地板 | 涨停→跌停 | 炸板卖出 / 止损执行 |
| 流动性枯竭 | 成交量为0 | 不生成买单 / 持仓报警 |
| 网络中断 | Broker断开60秒 | 自动重连 / 撤单保护 |
| 数据延迟 | 行情延迟>30秒 | 暂停交易 / 告警 |
| 连续亏损 | 连亏5笔 | 策略暂停 |
| 牛市→熊市切换 | Regime突变 | 情绪系数切换 / 仓位骤降 |

## 7.2 Kill Switch 测试

```
测试: 手动触发Kill Switch
验证: 
  ✅ 所有未成交订单被撤销
  ✅ 策略信号停止生成
  ✅ Broker下单通道断开
  ✅ 通知发出
  ✅ 恢复流程正常
```

# 第九章 上线验证

```

  ✅ 核心模块测试覆盖率达标

  ✅ Kill Switch有效

  ✅ T+1/涨跌停逻辑正确

执行:
  ✅ QMT连接稳定
  ✅ 订单生命周期正常
```

